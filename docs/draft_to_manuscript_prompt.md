# 从思路初稿整理为科普文稿的 Prompt

将下面的 Prompt 与初稿一起使用。本阶段只整理文稿，作者审阅后再进入朗读适配和配音。

---

请将作者零散的思路初稿整理成一篇完整、自然、准确、适合讲述的 Markdown 科普文稿，数学公式保留 LaTeX 格式。同时，主动构思与文稿对应的动态可视化例子，供以后制作视频参考。

## 核心规则

1. **沿用作者的大纲。** 输入中的 `#`、`##`、`###` 等表示内容层级与讲解顺序，这是作者原来的思路。保留井号标题的层级、结构和顺序。像 `## ？` 这样的标题占位符，表示内容位置已确定，请根据该段内容补一个合适的标题。

2. **落实作者说明。** `<* ... >` 中是背景、思路或额外要求。理解并落实这些说明，但不把说明本身及其标记写进成稿。

3. **把初稿写成完整正文。** 初稿可能重复、零散、表达不畅。可以去重、理顺语句、补齐必要的解释和例子，但要保留作者的核心意思与讲解路线。语言清楚自然，避免空话和无关扩写；知识和公式应准确，不编造事实，关键含义不明确时先询问。

4. **主动考虑视频怎么讲。** 写每个核心概念时，想一想有什么适合动态展示的例子：对象怎样移动，参数怎样变化，如何逐步构造、对照或放大，能帮助观众看懂什么。把有用的例子、演示思路和补充信息放在对应正文附近的 `<@ ... >` 中，已有视频提示也保留。这些内容不朗读、不进入字幕；正文应能独立读懂。

5. **让视频提示具体可用。** 简要说清展示什么、怎样变化、对应哪个知识点，不只写“加个动画”，也不必每段都加。例如讲导数时，可以建议让曲线上的点 B 靠近固定点 A，展示割线如何趋近切线。画面应符合正文的科学含义。

6. **输出 Markdown 文稿，公式使用 LaTeX。** 行内公式用 `$...$`，独立公式用 `$$...$$`，不改成配音读法。视频提示直接使用 `<@ ... >`，例如：

   ```markdown
   <@ 对应下文的割线趋近切线：让点 B 沿曲线靠近点 A，割线随之转动，最后与切线对照。 >
   ```

只输出完整 Markdown 文稿，不附改写说明，不用代码围栏包住全文。
