# 视频任务详细流程

本文件负责执行步骤、环境和交付规格，表达与风格按 [视频 Prompt](video_prompt.md)。视频任务先读取这两份文件；任务范围按根目录 `AGENTS.md`，所有命令和资源路径相对于仓库根目录。脚本参数见 [脚本接口](video_engine.md)。

## 接收音频模型的产物

1. 读取任务目录、`manifest.json`、`音频交接.md` 和 `改动说明.md`（若有），找到适配稿、`video/分镜草案.md`（若有）、TTS 稿、各段音频、同次字幕及时间轴，确认口播用途与只展示内容的要求，包括标题、表格、推导、清单和公式。`manifest.json` 缺少 `decodedDurationMs` 或 `headings` 时，运行 `python3 tools/audio_handoff.py outputs/<任务>` 补齐（只读取已有产物，不调用配音接口）。已有音频直接复用；明确要求配音但尚无音频时，按 [音频流程](audio_workflow.md) 准备或接收交接。
2. 画面与公式以 `manifest.source` 指向的实际拆分适配稿为准：它由第二步视频与分镜设计从科普文章作必要调整形成，或为已有适配稿的最新版本，不要求台词与输入文章逐字相同。完整公式、数据与条件须保持输入文章的含义，改写关系查 `改动说明.md`。不恢复更早初稿的错误或旧画面想法；即使 TTS 读法有误也不据此改公式。源位置按适配稿解释，配音使用与 TTS 匹配的音轨。
3. `alignment/` 仅记录实际拆分稿与 TTS 文本的对应，不含音频时间。服务字幕有句子级音频时间，句内位置按朗读字符插值，属于估算。
4. 读取原稿中的 `<!-- visual: ... -->` 及清单中各段 `videoHints`，按 [视频制作提示约定](video_hints.md) 将其用于分镜和动画，制作指令排除于字幕、配音和章节标题，明确标注的上屏内容则落实到画面。读取完整材料，不能只读制作指令或 TTS；推导须按整理稿保留各步、条件与顺序，过长时分镜展开，不因未朗读而只显示最终结论。若稿中只剩占位指令、缺少实际公式或数据，先记录缺失并回到第二步视频与分镜设计补齐，不猜造。旧任务若尚未记录提示，重跑文本检查与交接补齐；TTS 未变时继续复用配音。无配音任务也先分离提示与字幕正文。

无配音且输入仍是普通文章时，也先按 [视频与分镜 Prompt](manuscript_to_storyboard_prompt.md) 建立适配稿与分镜草案，用于画面与字幕，不生成配音或调用语音接口。

## 环境与技术

- 使用 Node.js 20+ 与 npm；共享依赖位于 `.local-deps/video`（`@napi-rs/canvas`、`ffmpeg-static`），首次在仓库根执行 `npm ci --prefix .local-deps/video`，按锁文件安装当前平台依赖及 FFmpeg。仓库渲染脚本直接加载共享依赖，各任务无需复制引擎或软链 `node_modules`，也不需要全局 FFmpeg。
- macOS 支持时优先使用 `h264_videotoolbox`，不可用时检测并使用实际可用的 H.264 编码器，如 `libx264`；不假定一定有硬件编码器。Agent 沙箱内硬件编码器可能初始化失败，用 `--encoder libx264` 即可，17 分钟成片在 Apple Silicon 上约需 2.5 分钟。
- 按名称检测已安装字体：画面正文默认宋体（Songti SC / Noto Serif CJK SC / Source Han Serif SC），字幕用黑体（Hiragino Sans GB / Noto Sans CJK SC），公式用 STIX。首次在仓库根运行 `python3 tools/video_engine/setup_fonts.py`，从已安装的宋体集合中拆出 Regular 与 Bold 到 `.local-deps/fonts/`（`.ttc` 在画布中只暴露第一个字面，macOS 的 Songti SC 只剩 Black）；首次运行会把 fontTools 装到 `.local-deps/fonttools`。找不到宋体时安装开放字体 Noto Serif CJK SC 后重跑；仍缺失时正文自动回退黑体，`render.mjs info` 的 `fonts` 中 `Song` 带 `note`，渲染时在终端提示，须在制作说明中注明。黑体或公式字体缺失时安装 Noto Sans CJK 与 DejaVu 或 STIX，或按 [脚本接口](video_engine.md#绘图与字体) 指定字体文件。字体不随仓库分发，不依赖固定系统路径；记录实际选择并检查字符覆盖。
- 任务代码放在本次 `video/src/`：`scenes.mjs` 写分镜表（句子范围、节拍、过渡），按章节拆分绘图代码（如 `ch_*.mjs`），本片共用的配色、字号和反复出现的图形放 `style.mjs`，封面放 `cover.mjs`。通用能力（新图标、公式命令、工具参数）回补到 `tools/video_engine/` 并补测试，不在任务里复制引擎。环境缺项时报告，不改全局配置。

## 视频制作

有配音时按以下顺序，每步产物都留在 `video/` 下，返修时可从任一步接续：

1. **准备时间轴**：视频简读使用 `node tools/video_engine/prepare.mjs --job outputs/<任务> --captions spoken`，得到 `prepared/` 下的整条音轨、句子时间轴、章节和跟随口播的字幕。需要原文公式字幕时显式选 `--captions source`（工具自身默认仍为 `source`）；此模式可能把简短口播替换为很长的字幕，须检查阅读负担。检查 `timeline.json` 的 `warnings`、`spokenFallbackFormulas` 与 `videoHints`，抽查 `sentences.md` 的文本和独立提示区；提示不进入句子或字幕，也不自带音频时间。
   英文姓名、术语补注按 [TTS 补注规则](tts_rewrite_prompt.md#英文补注不朗读字幕保留) 处理：检查对应 alignment 含 `caption_annotation`；两种字幕模式都会保留英文补注，中文名称沿用实际音频时间。不要为恢复补注把整篇切换到 source 模式；核查长补注的字幕宽度与阅读负担。

   可按 [视频 Prompt](video_prompt.md) 将个别冗长公式读法替换为等义的规范数学字幕；在任务源码中保存明确的字幕映射，供烧录与 SRT 共用，保留原始时间轴以便追溯。公式不跨条切断，保留条件与连接词，检查切换顺序、阅读时间和安全区；不要为少量替换把全文改为 source 模式。

2. **分镜表**：沿用第二步的分镜草案与适配稿，结合实际音轨细化时间和可执行动作，按视频 Prompt 写 `video/分镜表.md`（时间范围与来源｜原稿段落｜制作提示及位置｜口播与省读内容｜问题｜对象及起止状态｜条件变化与传递过程｜动作与完整公式｜保留结论｜准确性风险），全片统一配色、对象和反复出现的意象；时间用 `sentences.md` 的句子编号。逐条记录提示采用的效果或替代处理，动作落在对应正文的现有时间范围内。提示中标明的上屏表格、推导、清单等须实际制作，不能因其不在字幕中而漏掉；省读公式必须在主画面完整展示，关键条件可见；不朗读的公式绑定相邻讲解句，不能从零长度 TTS 区间推算展示时间，也不能依赖字幕工具自动生成公式镜头。
   同时保存 `video/时间对应表.md`，逐句检查关键短语，为需要强调的内容记录：句子编号与口播短语｜开始/结束时间｜时间来源及复核方式｜画面对象（稳定标识或公式项）｜动作及触发点｜复核结果与剩余偏差。时间来源区分同次服务字幕、句内字符插值估算、本地语音识别复核和实际试听校准；未复核时明确标记。分镜表还须写清条件变化及其传递过程。高亮与对象共用位置或边界数据，使其随对象移动；完成说明或切镜后清理。
   优先使用同次配音句子时间轴，以原音轨复核长句、公式读法、停顿、转折和关键动作。条件允许时使用本地语音识别核对关键短语与字幕边界，保存采用的工具、对应区间及判断依据；仅采纳与原台词匹配可靠、位于合理句子范围且时间有序的结果。不确定时保留原估算并记录，不用识别文本改写原稿或公式。音轨无封装偏移、字符串对齐和程序检查通过均不代表逐词同步。
3. **代表镜头**：先实现覆盖复杂推导、动态高亮和图形变化的典型镜头，`stills --scene N` 出静帧、联系表，再用 `sample --audio` 制作代表性带声片段（通常 30–60 秒，按完整讲解过程调整）。自查风格、字号、节拍、动作触发与原音轨的对应后继续全片，无需额外等待确认，除非用户要求先审。
4. **全片静帧**：逐章实现，`info` 校验分镜连续覆盖，`stills` 全量出图，逐镜头查看最后一个节拍及有过渡的节拍，检查文字与公式重叠、出界、字幕区遮挡（内容不低于 `SAFE.bottom`）和公式与原稿一致。另用带声样片检查复杂公式、推导、图表的定位、阅读、比较与理解时间是否足够；可提前显示、跨相邻解释句保留、减少动画步骤，不能把复杂推导挤在一两秒里。若仍不足且原因是讲解缺失，先局部回修适配稿与分镜，重跑受影响的 TTS 检查与交接；按任务授权处理新版配音，记录旧音轨不再匹配的范围，不擅自拉长或重合成已有音轨。
5. **成片与封面**：`full --audio prepared/audio.flac` 渲染，`cover` 出两张封面。对最终编码文件运行 `check.mjs` 检查时长、分辨率、帧率、音轨与章节，并做代表性抽帧；另用实际可用的 FFmpeg 完整解码音视频流，确认无解码错误，不能把抽帧成功当作完整解码。保存实际命令、结果与人工查看范围到 `video/制作说明.md`。

核验须覆盖全部场景和句子的时间覆盖、切换边界及关键结果出现顺序；高亮是否命中实际可见对象、随移动更新，有无空框、错框和跨场残留；连续动作的起点、中间过程、终点及必要停留；公式与图形及数值的一致性；文字重叠、出界、字幕安全区和章节转场。检查长时间停滞处是否需要机制变化，阅读与思考期间则保持稳定；总结动画应覆盖相应讲述。目录只能使用合适的桥接时间，不盖住尚在解释的内容，尤其复查“结论回顾 → 下一节提问”的边界。抽帧与样片数量由内容和风险决定，不机械追求固定数量；静帧不能替代连续运动检查，发现问题先修复，再复查受影响范围。

分镜阶段另确定一份全片共用的**核心章节目录**：按原稿顺序记录标题、源章节对应及纳入或排除理由，排除纯致谢、结束语、关注提醒和下期预告，含知识梳理的总结按内容判断。每个核心章节开头的转场均完整显示这份目录，固定各项位置，仅高亮即将讲解的章节；进度编号只计核心章节。章节多时按 [视频 Prompt](video_prompt.md) 使用可读的多列布局，不能分页或滚动隐藏部分章节。无配音分支也遵循此规则。

目录由任务 `video/src/` 的共用绘图函数与目录数据生成，避免各章独立维护而漏项或顺序漂移；保留到原稿章节的稳定对应，不用过滤后的目录下标直接索引原始章节。目录筛选不改变完整时间轴、配音、字幕或视频内嵌章节，收尾仍按原稿安排画面。标题只展示时，转场占用章首桥接句或边界已有时间；旧音轨读出标题时可使用其口播时间，不能破坏句子覆盖和音画同步。代表镜头预览须包含一张完整目录转场；全片静帧与成片抽检须覆盖每个章节转场，核对目录完整性、当前高亮、字号、布局、字幕安全区与实际停留时间。

其他情形：

- 多段音频不能直接拼接每段从零开始的时间轴；`prepare.mjs` 已按实测时长累加偏移。仅有音频没有服务字幕时，先检查可用的转写/对齐工具；估算时间须注明，不为补时间轴重新合成。
- 无配音时制作无声视频与烧录字幕，先排除 `<!-- visual: ... -->` 提示，去掉桥接引用前缀，再将台词写入 `lines`，按约 4.6 字/秒估算字幕阅读时间，并结合实际上屏材料增加观察与比较时间；不能只按字幕字数决定复杂画面的时长，提示指令本身不计阅读时长。

## 交付与限制

默认输出到当前任务目录下新的 `video/`，保留已有文本、音频和历史成片：

- 成片 `film.mp4`：1920×1080，30fps，内嵌章节，烧录字幕。
- 字幕 `字幕.srt`；`章节.txt`，可直接用于视频简介。
- 封面两张：`cover_16x9.png` 和 `cover_4x3.png`。
- `src/` 渲染代码、`分镜表.md`、`时间对应表.md`、`prepared/` 时间轴、`preview/` 静帧与代表性带声样片（无配音任务为无声样片）、`check/` 成片核验记录、`制作说明.md`（运行命令、依赖、实际检查方式与范围、结果和已知限制）。

无配音任务的时间对应表记录字幕短语、估算时间、对象与动作，省略语音复核，代表预览为无声片段。

如实说明未完成的试听、渲染、同步或检查，明确是否做过真人完整试听、实时观看及逐词校准，不以自动检查替代这些声明。长任务及时保存已完成步骤、产物路径、待修问题与下一步，供中断后接续。最终回复简要列出本轮解决的具体问题、经过语音复核的时间点与仍为估算的范围，提供成片及代表预览的可直接打开链接，不发布或对外发送。

交付前检查 SRT、烧录字幕、章节标题与音轨中无视频提示泄漏，复查提示对应的动画效果；逐处确认省读公式完整可见、口播重点与高亮一致、阅读时间足够，不把“未朗读”当成可以跳过画面。不要把制作说明混入观众看到的正文。
