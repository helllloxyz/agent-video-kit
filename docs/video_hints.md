# 文稿注释、桥接与视频交接

文稿流程分三步：[整理文章](draft_to_manuscript_prompt.md) → [视频与分镜设计](manuscript_to_storyboard_prompt.md) → [TTS 音频化](tts_rewrite_prompt.md)。第一步的 `visual` 只是补充想法，正文应独立完整；第二步设计画面并确定台词，第三步只做必要音频化转换。以下读与不读的规则针对第二步确定的适配稿。

## 写法与职责

- `<!-- author: ... -->`：作者的背景、思路或要求。整理文稿时落实后去除，不作为画面提示交接。
- `<!-- visual: ... -->`：只展示的资料、视频构想及制作安排。保留在适配稿与拆分稿，排除于 TTS、配音和口播字幕；以 `videoHints` 交接。
- `>` 引用段落：需要朗读的桥接、过场台词，每行带引用前缀；TTS 去掉前缀，保留文字和顺序。不朗读的转场指令写在 `visual` 中。适配稿以此用途使用引用；第一步文章中的引用按实际含义理解，真正的引文在适配时用引号或放入上屏资料，避免混淆。
- 标题保持正常 Markdown 层级，默认只展示。视频口播检查加 `--visual-headings`；纯音频、明确读标题或复查原有读标题的任务不加。

标签使用小写英文和半角冒号；内容可以是中文，支持行内、独立行及跨行。HTML 注释以 `<!--` 开始、`-->` 结束，不嵌套，内容不能包含注释的起止标记；普通大于号、表格和 LaTeX 可以放在里面。注释在 Markdown 源码中可见，常规渲染预览中隐藏。代码、公式和网址内部的标记按字面语法处理，不提取为注释。未闭合或嵌套会报错。

普通 HTML 注释也不朗读，但不交接为画面资料；不能用它代替 `visual` 保存上屏内容。`<@ ... >` 与 `<* ... >` 均已停用，不再解析或交接为提示。使用旧稿时先按内容改为 `<!-- visual: ... -->` 或 `<!-- author: ... -->`，再拆分和提取；工具遇到源稿中未迁移的旧标记会报错，不自动删除其内容或改写历史文件。代码、公式等受保护的字面内容不受影响。普通 `<...>` 不作为提示，`<#0.8#>` 仍是停顿标记。

## 画面内容与时间安排

第一步文章可以附 `visual`，已有想法可细化、去重，但正文的完整性不依赖这些注释。第二步借鉴这些素材，仍须从视频和口播重新思考、优化与扩展；可以重组或替换表现方案，不能将照搬备忘视为完成视觉设计。第二步尽量保留原文，只为画面表达搬移必要的上屏材料、局部调整台词、补必要的观察引导与桥接，不整体重写或过度通俗化。第三步依据这些设计生成读法、复核讲解节奏；发现必要解释不足时先局部回修第二步产物，再音频化。

适配稿的 `visual` 要体现分镜意识：镜头回答什么问题，起始对象与状态，随哪句口播发生什么变化，重点落在哪里，最后保留什么，以及如何承接下一镜头。根据内容安排构造、移动、对照、放大和分步展示，不为效果改变科学含义，不在音轨产生前虚构精确时间。视频阶段还需按实际时长落实。

不朗读的完整表格、推导、列表、公式或图片引用保存在适配稿的 `visual` 内，关键解释和桥接留在外面。注释可区分“上屏内容”与“呈现安排”：前者包含实际公式、各步推导、文字和数据，后者说明怎样展示。二者是阅读标签，工具仍将整个注释原文交接。材料已完整保存在同份适配稿时可引用位置；不能只写展示指令，也不能只指向未交接的文章。

行内注释对应所在句或段落，独立注释默认对应下文，文末注释对应前段；显式指定的范围优先。制作指令不直接上屏，明确指定的展示资料须实际制作。承担口播省略信息的展示必须落实，可选动画形式可以调整，替代处理在分镜中记录。

注释没有独立朗读时长。画面绑定相关口播或桥接句，标题转场使用章首桥接或边界已有时间。只展示的资料不会自动成为镜头；不能按注释字数加停顿，也不能把复杂表格或推导挤进一句话。必要时提前显示、跨句保留或减少动画步骤；讲解不足时补足有意义的观察引导与解释，并同步适配稿，不以“观众可以暂停”代替合理节奏；纯视觉镜头另行编排，不提交空文本合成。

## 各阶段处理

1. **文章与分镜**：第一步输出完整文章，可附视觉备忘。第二步保存 `source/<原文件名>_适配稿.md`、`video/分镜草案.md` 与 `改动说明.md`；逐项检查正文改动的必要性及材料完整性，原文未受画面影响的部分保持不变。草案按台词和展示节拍定位，没有音轨时不编精确时间。
2. **TTS 音频化与检查**：第三步将确定的适配稿按真正的顶层 `##` 拆分，注释内标题不作边界，完整注释计入每份 3000 字符上限。仅从 TTS 排除注释，桥接只去 `>`；完整材料仍在适配稿、拆分稿与交接中。`check_tts.py` 按参数处理标题，除必要替换片段外逐字核对台词，`visual` 单独保存为 `videoHints`。脚本不证明第二步的必要调整正确，不能因检查通过而省去语义审阅。联网合成前拒绝残留注释或已停用标记的 TTS。
3. **音频交接**：`audio_handoff.py` 保存 `headings` 与各段 `videoHints`。提示包含 `text`、`sourceText`、`sourceRange`、`sourceLines` 和 `originalSourceLines`；字符范围为从零开始、右端不含的 Python Unicode 位置。引用台词保留在源稿，并通过 TTS 和 alignment 对应，不产生独立提示时长。
4. **视频准备**：`prepare.mjs` 将提示汇总到 `timeline.json.videoHints` 和 `sentences.md` 提示区，不加入句子或字幕。只展示的标题根据源行号、alignment 和后续口播定位；没有可用口播的纯视觉章节需单独安排，不能伪造标题语音时间。将第二步分镜草案细化为有实际时间的执行分镜，记录提示位置、对应句子、实际效果和处理说明。
5. **字幕与复查**：视频简读用 `--captions spoken` 跟随实际口播，完整展示资料另行绘制。无声视频先排除注释、去除桥接引用前缀，再编写 `lines` 与字幕。引擎拒绝含 HTML 注释或已停用标记的字幕、章节标题和 `lines`。核查配音、字幕无指令泄漏，并核查上屏资料、桥接与画面节奏匹配。

## 公式展示提示与任务副本

依赖画面的公式省读须有 `visual` 承接。注明原式位置、完整展示要求、口播重点和展示顺序；必要条件、范围和符号须可见。已有提示足够时复用，简单短式完整读出时不机械补提示。提示放在公式定界符外；可引用邻近原式，避免重复抄写。空公式读法绑定相邻讲解句，不推算逐符号语音时间。

第二步从文章形成适配稿，尽量维持原文，只为画面需要作材料搬移、局部调整与桥接补充。逐章核查完整公式、推导、图片引用、数据和条件没有丢失或改变；在 `改动说明.md` 逐项记录必要改动及原因。第三步发现看图讲解不足或设计缺口时，先回写第二步的适配稿和相关分镜，再提取 TTS；不能只改 TTS 或扩大脚本豁免来掩盖差异。

只有用户明确要求“只补提示”或对已有适配稿仅做提示增补时，才使用受限副本规则：在新副本只插入 `visual`，不改原有正文、公式及提示；用 `strip_video_hints` 去除两份稿件的画面提示后，以仅统一空白的文本比较确认一致，并核对原提示全文、顺序与位置保留。此特例不能限制正常视听适配，也不能用来把正文藏进注释绕过检查。

完整适配和必要提示应在拆分前完成，均计入字符上限。`audio_handoff.py --source` 指向实际拆分的适配稿或其最新副本，`manifest.source` 与 `originalSourceLines` 也属于该版本；在 `改动说明.md` 记录输入文章、适配稿和拆分稿的路径，不把适配稿行号说成输入文章行号。

空公式读法的警告逐条记录省读理由、对应口播和展示位置。脚本通过只代表字符串与格式检查完成，不代表语义、画面或时间已验证。

## 稿件更新与产物复用

- 文章或适配稿若再改正文、桥接、公式或画面资料，保存新版本并记录采用的路径，重新检查受影响的拆分、TTS、alignment 与交接，不能沿用旧的“通过”状态。源位置变化也要重建对应记录。
- 只改 `visual` 且实际提交的 TTS 文本完全未变时，可复用已有音频和同次字幕；画面资料与分镜仍须更新。若拆分边界改变，先确认新旧分段仍能准确对应，不仅比较拼接后的文字。
- 口播或分段发生变化时，旧音频不能冒充新版配音。按用户当前授权处理后续合成；仅修改文稿或流程时停在相应阶段，保留历史产物，不自动付费重配。视频准备文件与分镜必须使用同一版本的源稿、TTS 和音频。

## 已有任务补入提示

同步更新本次源稿副本和对应 `parts/`，保持拆分边界与文件名；确认按顺序拼回与副本一致，复查字符上限。依次重跑：

```bash
python3 tools/check_tts.py outputs/本次任务/parts outputs/本次任务/tts \
  --alignment-dir outputs/本次任务/alignment
python3 tools/audio_handoff.py outputs/本次任务 --source outputs/本次任务/source/讲稿.md
node tools/video_engine/prepare.mjs --job outputs/本次任务 \
  --captions spoken --output-dir outputs/本次任务/video/prepared_with_hints
```

标题只展示时第一条加 `--visual-headings`；已有音轨读了标题时不加。上一条通过后再继续，分镜的 `loadPrepared` 指向新目录。TTS 未变就复用已有音频；改变口播后不能宣称旧音频匹配。仅更新文档或提示不触发付费合成，也不能只删字幕来修复已读出的制作指令。
