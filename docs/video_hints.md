# 讲稿中的视频制作提示

用户可在讲稿中用 `<@ 提示内容 >` 指导分镜、动画、构图、转场和强调方式。这部分是制作提示，不属于需要朗读或显示为字幕的正文。普通 `<...>` 不作为此类提示；MiniMax 的 `<#0.8#>` 仍是停顿标记。

初稿中的 `<* ... >` 则是作者提供的背景、思路或额外要求，由初稿整理模型理解落实后去除，不作为视频提示交接。

## 写法与作用范围

支持行内、独立行和跨行提示，例如：

```markdown
## 割线与切线
让第二个点逐渐靠近第一个点。<@ 保留曲线，让点 B 沿曲线向点 A 移动，割线随之转动 >
当两点足够接近时，割线趋近切线。

<@
下一段可以用局部放大展示趋近过程，最后突出切线。
>
我们再看局部的变化。
```

- 行内提示默认对应所在句或段落；独立提示默认指导紧随其后的正文，文末提示则对应前一段。提示明确指定章节、对象或作用范围时按其说明处理。
- 提示可以提出可选效果，由视频模型结合原稿含义、现有音轨和画面节奏落实；不凭提示增写旁白或改变原稿的数学、物理关系。含义不明确或无法实现时，在分镜或制作说明中记录判断与替代效果。
- 提示本身不复制到字幕、朗读稿、章节标题或画面说明文字中；若提示要求突出某个正文术语，可按正文做图形或文字标注。
- 提示没有独立的朗读时长，不自动添加停顿或延长音轨。有配音时把动作安排到相关正文的现有时间范围；无声视频也只按排除提示后的正文估算字幕阅读时间。纯视觉镜头需要单独编排时长。
- 标记必须成对，不支持嵌套；缺少 `>` 或嵌套时先修正源稿，检查工具会报错。公式定界符、代码、Markdown 自动网址链接和 HTML 注释内部按原有语法处理，不提取提示。提示从 `<@` 开始，到第一个 `>` 结束；内容中不要使用字面的 `<@` 或 `>`，大于关系可写作“大于”或 LaTeX 的 `\gt`，以免与边界冲突。

## 各阶段处理

1. **原稿与拆分**：原文件不变，`parts/` 保留标记和提示全文。仍按真正的顶层 `##` 切分，提示内部的标题不作章节边界；3000 字符限制仍按完整源稿计算，包含提示。
2. **朗读适配**：从 `_TTS.txt` 中排除标记及其全部内容，只转换剩余正文；不要改成“画面显示……”等解说，不因排除提示改动相邻正文或标点。在 `改动说明.md` 中记录提示及源位置，供视频制作查阅。
3. **字符串检查**：`check_tts.py` 将提示视为零朗读内容，不视为可自由填入读法的替换片段；提示单独写入 alignment JSON 的 `videoHints`，不进入 `segments`。正文仍逐字核对，TTS 中残留 `<@` 会报错。`minimax_tts.py` 也会在联网前拒绝含该标记的输入，不自动删除后付费合成。
4. **音频交接**：`audio_handoff.py` 从拆分原稿提取每段的 `videoHints`，写入 `manifest.json`。记录 `text`（提示正文）、`sourceText`（含标记原文）、`sourceRange`（拆分稿中从零开始、右端不含的 Python Unicode 字符范围）、`sourceLines`（拆分稿行号）、`originalSourceLines`（拼回原稿的行号）。不生成虚构的音频时间。
5. **视频准备与分镜**：先阅读原稿和提示；`prepare.mjs` 将提示汇总到 `prepared/timeline.json` 的 `videoHints`（附 `part` 与拆分稿路径 `source`）及 `sentences.md` 的独立提示区，不加入 `sentences` 或 `captions`。分镜表记录提示位置、对应正文/句子编号、采用的效果及处理说明。
6. **字幕与检查**：有配音时字幕来自不含提示的 TTS 及 alignment，公式仍按原稿还原；无声时先排除提示，再编写 `lines` 和字幕。视频引擎会拒绝仍含 `<@` 的 `lines`、字幕或章节标题，修正后再渲染，不自动删去提示并改变时间安排。检查 SRT、烧录字幕、章节标题和试听内容，确认没有提示泄漏，并检查提示对应的画面效果。

## 已有任务补入提示

将提示同步到原稿与对应的 `parts/` 拆分稿，保留原有拆分边界和文件名，确保按顺序拼回后仍与原稿一致。重跑文本检查与交接，使 alignment、`manifest.json` 和视频准备文件保持一致。例如，在仓库根目录执行（替换为实际任务与原稿路径）：

```bash
python3 tools/check_tts.py outputs/本次任务/parts outputs/本次任务/tts \
  --alignment-dir outputs/本次任务/alignment
python3 tools/audio_handoff.py outputs/本次任务 --source 讲稿.md
node tools/video_engine/prepare.mjs --job outputs/本次任务 \
  --output-dir outputs/本次任务/video/prepared_with_hints
```

逐条执行，上一条通过后再继续。视频准备使用新目录，分镜中的 `loadPrepared` 路径随之更新；确认可覆盖旧准备文件时，也可沿用原目录并显式传入 `--overwrite`。这些步骤不调用配音接口。

若实际提交的 TTS 文本未变，复用已有音频，不为补提示重发配音请求；交接工具会检查它是否与各段 `audio/NNN/request.json` 的 `text` 一致。已有音轨确实读出了提示时，不能仅删字幕后宣称修复。
