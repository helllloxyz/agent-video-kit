# 讲稿中的视频制作提示

用户可在讲稿中用 `<@ 提示内容 >` 指导分镜、动画、构图、转场和强调方式。这部分是制作提示，不属于需要朗读或显示为字幕的正文。普通 `<...>` 不作为此类提示；MiniMax 的 `<#0.8#>` 仍是停顿标记。

初稿中的 `<* ... >` 则是作者提供的背景、思路或额外要求，由初稿整理模型理解落实后去除，不作为视频提示交接。

## 写法与作用范围

支持行内、独立行和跨行提示，例如：

```markdown
## 割线与切线
让第二个点逐渐靠近第一个点。<@ 保留曲线，让点 B 沿曲线向点 A 移动，割线随之转动 >
当两点足够接近时，割线趋近切线。

<@
下一段可以用局部放大展示趋近过程，最后突出切线。
>
我们再看局部的变化。
```

- 行内提示默认对应所在句或段落；独立提示默认指导紧随其后的正文，文末提示则对应前一段。提示明确指定章节、对象或作用范围时按其说明处理。
- 提示可以提出可选效果，由视频模型结合原稿含义、现有音轨和画面节奏落实；不凭提示增写旁白或改变原稿的数学、物理关系。因口播省读而承担信息的公式展示必须落实，动画形式可以调整。含义不明确或无法实现时，在分镜或制作说明中记录判断与替代效果；必要信息尚未展示时不能视为完成。
- 提示本身不复制到字幕、朗读稿、章节标题或画面说明文字中；若提示要求突出某个正文术语，可按正文做图形或文字标注。
- 提示没有独立的朗读时长，不自动添加停顿或延长音轨。有配音时把动作安排到相关正文的现有时间范围；无声视频也只按排除提示后的正文估算字幕阅读时间。纯视觉镜头需要单独编排时长。
- 标记必须成对，不支持嵌套；缺少 `>` 或嵌套时先修正源稿，检查工具会报错。公式定界符、代码、Markdown 自动网址链接和 HTML 注释内部按原有语法处理，不提取提示。提示从 `<@` 开始，到第一个 `>` 结束；内容中不要使用字面的 `<@` 或 `>`，大于关系可写作“大于”或 LaTeX 的 `\gt`，以免与边界冲突。

## 各阶段处理

1. **原稿与拆分**：原文件不变，`parts/` 保留标记和提示全文。仍按真正的顶层 `##` 切分，提示内部的标题不作章节边界；3000 字符限制仍按完整源稿计算，包含提示。
2. **朗读适配**：从 `_TTS.txt` 中排除标记及其全部内容，只转换剩余正文；不要改成“画面显示……”等解说，不因排除提示改动相邻正文或标点。在 `改动说明.md` 中记录提示及源位置，供视频制作查阅。
3. **字符串检查**：`check_tts.py` 将提示视为零朗读内容，不视为可自由填入读法的替换片段；提示单独写入 alignment JSON 的 `videoHints`，不进入 `segments`。正文仍逐字核对，TTS 中残留 `<@` 会报错。`minimax_tts.py` 也会在联网前拒绝含该标记的输入，不自动删除后付费合成。
4. **音频交接**：`audio_handoff.py` 从拆分原稿提取每段的 `videoHints`，写入 `manifest.json`。记录 `text`（提示正文）、`sourceText`（含标记原文）、`sourceRange`（拆分稿中从零开始、右端不含的 Python Unicode 字符范围）、`sourceLines`（拆分稿行号）、`originalSourceLines`（拼回原稿的行号）。不生成虚构的音频时间。
5. **视频准备与分镜**：先阅读原稿和提示；`prepare.mjs` 将提示汇总到 `prepared/timeline.json` 的 `videoHints`（附 `part` 与拆分稿路径 `source`）及 `sentences.md` 的独立提示区，不加入 `sentences` 或 `captions`。分镜表记录提示位置、对应正文/句子编号、采用的效果及处理说明。
6. **字幕与检查**：有配音时字幕来自不含提示的 TTS；视频简读默认使用 `prepare.mjs --captions spoken`，字幕跟随实际口播，完整公式在主画面展示。需要原文公式字幕时可选 `--captions source`，但仍须单独制作公式画面；无声时先排除提示，再编写 `lines` 和字幕。视频引擎会拒绝仍含 `<@` 的 `lines`、字幕或章节标题，修正后再渲染，不自动删去提示并改变时间安排。检查 SRT、烧录字幕、章节标题和试听内容，确认没有提示泄漏，并检查提示对应的画面效果。

## 公式展示提示与任务副本

视频简读让画面承担完整公式、口播说明重点。音频适配阶段就要为省读的公式准备展示提示，不等到视频阶段猜测省略了什么。简单短式若已完整读出且无特殊展示需要，不必机械新增提示；已有提示能覆盖要求时直接复用。

每条公式提示应包含：

- **定位与展示内容**：明确“下式”“本段第几个公式”等位置；以邻近的原始 LaTeX 为准，完整展示，不必在提示中重复抄长公式。
- **口播与重点**：标明“口播概括为……”或“该式不朗读，承接上一句……”，指出对应的项、条件或变化。
- **展示顺序**：先显示什么、随后突出什么、最后保留什么。依赖画面但没读出的条件和范围必须可见，不能只闪一下或藏在字幕里。

例如，正文已说明将这 n 个数相加时：

```markdown
<@ 对应下式：完整展示求和式，口播简读为“把这些数加起来”；讲到相加时突出求和符号和各项，保留下标范围一到 n，继续停留到本段解释结束。 >
$$\sum_{i=1}^{n}x_i$$
```

提示必须放在公式定界符外。它描述展示安排，不自带朗读时长，不要求按提示长度插入停顿。公式不朗读时没有可用的朗读字符区间，应绑定相邻解释句的时间范围；一句话概括多行推导时按意义安排节拍，不伪造每个符号的语音时间。

需要新增提示时，保留用户源文件，在本次任务目录建立 `source/` 下的同名 Markdown 副本，只插入 `<@ ... >`，不改正文、公式或已有提示。用 `strip_video_hints` 去除两份文件的提示后，以仅统一空白的文本比较确认正文和 LaTeX 一致，并核对已有提示全文、顺序和对应位置保留；此项同样通过脚本检查，不由模型凭阅读代替。随后从任务副本拆分到 `parts/`，按拆分稿生成 TTS 和 alignment。新增提示也计入每份 3000 字符限制，须在拆分前补齐；若超限，遵循原有超限处理规则。

交接时 `audio_handoff.py --source` 指向实际拆分的任务副本，确保 `parts/` 拼回后与它一致。`manifest.source` 及 `originalSourceLines` 此时指任务副本及其行号；在 `改动说明.md` 记录用户原稿路径、任务副本路径和新增提示位置，不把副本行号说成用户原稿行号。视频阶段从副本取得完整公式和提示；公式内容与用户原稿一致。

空公式读法会产生检查警告，须在 `改动说明.md` 逐条记录理由、展示提示位置及对应的相邻讲解句。当前工具不会自动为零长度读法生成字幕或公式镜头，必须在分镜中落实。任务若只有不朗读的公式而没有可发音正文，不提交空文本合成，记录为待安排的纯视觉内容。

## 已有任务补入提示

保留用户原稿；将提示同步到本次任务的源稿副本与对应的 `parts/` 拆分稿，保留原有拆分边界和文件名，确保按顺序拼回后仍与副本一致，并复查含新增提示后的字符上限。重跑文本检查与交接，使 alignment、`manifest.json` 和视频准备文件保持一致。例如，在仓库根目录执行（替换为实际任务与副本路径）：

```bash
python3 tools/check_tts.py outputs/本次任务/parts outputs/本次任务/tts \
  --alignment-dir outputs/本次任务/alignment
python3 tools/audio_handoff.py outputs/本次任务 --source outputs/本次任务/source/讲稿.md
node tools/video_engine/prepare.mjs --job outputs/本次任务 \
  --captions spoken --output-dir outputs/本次任务/video/prepared_with_hints
```

逐条执行，上一条通过后再继续。视频准备使用新目录，分镜中的 `loadPrepared` 路径随之更新；确认可覆盖旧准备文件时，也可沿用原目录并显式传入 `--overwrite`。这些步骤不调用配音接口。

若实际提交的 TTS 文本未变，复用已有音频，不为补提示重发配音请求；交接工具会检查它是否与各段 `audio/NNN/request.json` 的 `text` 一致。已有音轨确实读出了提示时，不能仅删字幕后宣称修复。将旧的完整读法改成简读会改变 TTS，旧音频就不再与之匹配；仅更新流程文档或提示不触发重新配音，只有用户要求更新配音时才按音频流程处理。
