# 从科普文稿到视频与分镜的 Prompt

输入是一篇已整理好的科普文章，可附 `visual` 想法。请设计画面与讲解如何共同呈现内容，形成视听适配稿和分镜草案，供后续 TTS 与视频制作使用。

**尽量维持原文。** 保留作者的措辞、术语、论证顺序、例子、条件与确定程度，不为了口播重新讲一遍或过度通俗化。改动集中在需要画面承载的内容，以及为画面补充的必要引导、解释与桥接；其他正文直接保留。具体发音、公式读法和停顿交给下一步 TTS。

## visual 的目的

`visual` 是交给后续视频制作的内容与设计依据：把抽象关系变成观众能观察的对象和变化，保存口播未逐项念出的完整材料，并说明画面如何帮助理解。它应让制作者知道为什么这样展示、如何构造、怎样配合讲解，而不只是装饰建议或“此处放一张图”。

可参考本地[结合律视听文稿](../outputs/结合律_口播稿_20261019_122736/从结合律到可加标度_视听文稿.md)的设计方法：从概念中提取可操作的对象，把公式关系映射为位置、间距、箭头或局部变化；用同一组对象连续承接推理，必要时放大、对照，再回到整体。参考的是构造与讲解的对应方式，不照搬其题材、结论或动画。该文件是本地参考，缺失时按这里的原则执行。

按需要写清：完整上屏材料 → 对象与初始状态 → 随讲解发生的变化 → 观察重点及其含义 → 保留结果与下一镜头。演示所用参数、数值和运动须有公式或数据依据，区分示意与精确结果；不要求每段套齐字段。

## 适配稿的写法

| 写法 | 用途 |
| --- | --- |
| 原有井号标题 | 保留大纲层级和顺序，默认在画面展示 |
| 普通正文 | 需要朗读的讲解，以原文为主 |
| `>` 段落 | 需要朗读的画面引导、桥接与过场；每行加前缀 |
| `<!-- visual: ... -->` | 不朗读的完整上屏材料、图片引用与呈现安排 |

原文中的真正引文按其含义保留，可用引号与桥接区分。制作指令不写进朗读正文。标记语法见 [视频制作提示约定](video_hints.md)。

中文姓名或术语后的英文补注保留在适配稿和预期字幕中，后续 TTS 默认省读重复英文。不要为省读删除原文或只藏入 visual；第三步按 [英文补注规则](tts_rewrite_prompt.md#英文补注不朗读字幕保留) 建立明确映射。

## 设计要求

1. **有需要才调整看与听的分工。** 长公式、较长的推导、表格、图片和不宜逐项朗读的材料可以交给画面。原文已有解释优先沿用；只有转为视觉呈现后缺少引导或出现断句，才局部补充或调整。关键概念、推理依据与成立条件仍需讲清，不以画面替代必要论证，不仅因为段落长就删减。

2. **完整保存上屏材料。** 不朗读的公式、各步推导、表格和数据完整放入 `visual`，不能只剩结论、省略号或“这里展示推导”。保留图片路径、链接或附件引用及必要图注，明确要展示的局部；缺少素材时记录缺失，不猜造图片内容。材料已完整保存在同份适配稿时可以引用位置，不只指向更早的文章。

3. **继续思考和完善 visual。** 第一阶段的 `visual` 只是初步想法，结合视频的实际观看过程继续优化、扩展，必要时重组表现方案。按内容主动设计对象构造、移动、参数变化、对照或放大；已有提示可以细化、合并与去重。视觉表现可以发挥，不能据此改变正文的科学含义或强行改成更通俗的讲法。

4. **写出镜头中的变化与衔接。** 每个镜头围绕明确问题，写清起始对象与状态、对应哪句讲解、何时出现或突出什么、观众应注意哪里、结束时留下什么，以及如何进入下一镜头。表格安排阅读行列，推导逐步展开并保留对照，图片指出观察重点。复杂内容分成有意义的展示节拍，不一次堆满屏幕，也不强行为每段配动画。

5. **只补必要的桥接和解释。** 优先提取或沿用原文中的衔接；画面变化需要时，用 `>` 补必要的观察引导、局部解释或过场。让观众知道看什么、这一变化意味着什么、为什么进入下一步。避免重复报标题、额外总结、互动套话或重新解释已经讲清的内容；不把画面指令改成旁白照读。

6. **保留完整材料，控制展示负担。** `visual` 可用“上屏内容”和“呈现安排”区分材料与指令，这只是阅读标签。长内容可以提前出现、跨句保留或分镜呈现；讲解按观众观察顺序展开：先定位对象或行列，再指出关键变化、对应关系与结论。观众能从画面获取细节，不必逐符号、逐格复述；但复杂推导或图表不能只配一句结论就切走。根据理解负担安排足够的解释、观察节拍和结果保留，不能默认观众靠暂停补完必要信息，也不靠无关话语凑时长。尚无音轨时按章节、段落、台词和展示节拍定位，不虚构秒级时间，也不按注释字数增加静音。

## 复核与交付

对照输入文章，逐项检查正文改动是否确为画面配合所需，其余恢复原文；核查公式、推导、图片引用、数据、条件与论证没有遗漏或改变。连读正文与桥接，确认指代清楚、过场连贯，制作指令未混入台词。内容歧义另行记录，不通过改写掩盖。

保留输入文章，在唯一的 `outputs/<任务>/` 中保存以下产物，已有任务沿用目录，不覆盖历史版本：

- `source/<原文件名>_适配稿.md`：完整台词、上屏材料及 `visual`，作为后续拆分和 TTS 的唯一正文基准；已有合格适配稿可复用。
- `video/分镜草案.md`：按顺序记录镜头、对应章节与台词、材料位置、起止状态、动作重点和镜头衔接。与适配稿保持对应，不重复抄写长公式，也不另写一套台词。
- `改动说明.md`：输入文章与适配稿路径，正文必要改动及理由，移入画面的材料、图片引用、新增桥接与待确认项。

本阶段完成视频表达与分镜设计，不调用配音或渲染。后续 [TTS Prompt](tts_rewrite_prompt.md) 结合本阶段画面做必要音频化转换与看图讲解复核；发现讲解不足时先回写适配稿和相关分镜，再提取 TTS；音轨完成后，视频制作按实际时间完善执行分镜并渲染。
