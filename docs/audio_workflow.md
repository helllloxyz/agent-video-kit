# 音频任务详细流程

本文件供负责音频的模型按需读取；入口为根目录 `AGENTS.md`。所有命令和资源路径相对于仓库根目录。只给讲稿默认完成本流程，用户明确要求只转写、先审稿或只改工具时遵循其限定。

## 输入与输出

本流程使用第二步确定的适配稿，执行第三步 TTS 音频化及后续配音。若输入仍是普通科普文章，先按 [视频与分镜 Prompt](manuscript_to_storyboard_prompt.md) 独立完成第二步；已有适配稿与分镜直接复用。第二步尽量保留原文，仅为画面作必要调整；TTS 不承担文章重写和分镜设计。纯音频用途可直接采用完整定稿，跳过分镜设计。

输入文章、适配稿与 TTS 分别保留。逐字核对针对适配稿与 TTS；文章到适配稿另做改动必要性、语义和内容完整性审阅。

- 先读取实际源稿、`docs/tts_rewrite_prompt.md` 和 `docs/tts.md`；首次使用再读 `README.md`。不需要读取视频 Prompt。
- 单次任务使用唯一 `outputs/<任务名或时间戳>/`，保留输入文章；适配稿放 `source/`，分镜草案放 `video/分镜草案.md`；拆分稿放 `parts/`，朗读稿放 `tts/`，字符串对齐放 `alignment/`，配音逐份放 `audio/001/`、`audio/002/` 等空目录。
- 输入为目录时按相对路径和文件名数字自然排序，仅处理指定的讲稿；保留相对目录关系，排除项目配置、版本控制和已生成输出。
- 复用当前任务已经检查通过的朗读稿及已成功生成的配音，不因阶段切换而重写或重复付费。
- 默认复用第二步确定的视听分工：井号标题只展示，`<!-- visual: ... -->` 中的表格、推导、清单等画面内容不朗读，正文保留观察引导与桥接，完整公式由画面承载；用户明确要求纯音频或逐项读式时改用完整读法。本次只交付音频不改变默认用途，交付时注明。演示构想、完整上屏材料和桥接由第二步完成，按 [视频制作提示约定](video_hints.md) 完整交接；提示及标记不进入 TTS、配音或字幕。无需读取视频详细步骤即可完成此处理与交接。

## 流程一：TTS 音频化

1. 完整读取 `docs/tts_rewrite_prompt.md`，确认用途，读取确定的适配稿、分镜草案和改动说明，核查台词、上屏材料与桥接齐全。缺少分镜适配时先完成第二步；对照画面检查复杂公式、图表的观察顺序和讲解是否充分；需要补解释或桥接时先局部回修适配稿与相关分镜，再进行拆分和音频化，不把新增台词只写进 TTS。纯音频直接核查源稿能独立听懂，不新增画面设计。
2. 适配稿稳定后按完整章节拆分，再提取对应 `_TTS.txt` 并更新 `改动说明.md`，保留前两步记录；此时排除注释、按用途排除标题、去桥接 `>` 前缀，保留确定的台词，仅作必要发音、公式读法和格式标签转换。仅在顶层 `##` 之间切分，合并相邻完整章节；默认每份 3000 字符，包含画面材料。单章超限时报错，须显式提高上限或调整源稿章节，不拆段落、不丢画面材料。TTS 另查 9000 UTF-16 字符限制。

   ```bash
   python3 tools/split_markdown.py <任务目录/source/讲稿_适配稿.md> --output-dir <任务目录/parts> --max-chars 3000
   ```

3. 对拆分后的适配稿与对应 TTS 运行检查，不用输入文章直接比对改写后的台词；视频用途下标题只展示时加 `--visual-headings`，纯音频或已有读标题的任务不加；拆分过的稿件使用对应拆分源稿核对。示例：

   ```bash
   python3 tools/check_tts.py <任务目录/parts> <任务目录/tts> --alignment-dir <任务目录/alignment> --visual-headings
   ```

4. 处理检查错误，逐条审阅公式简读是否准确、必要条件是否清楚、展示提示是否承接省略细节、讲解与展示节拍是否匹配，不能只用一句话带过需要逐步观察的复杂画面，记录警告与待确认项。空读法警告不能直接忽略，须确认正文连贯且有展示安排；脚本只检查字符串与格式，不判断这些语义条件。有影响发音含义的未决项时不直接提交合成，可继续处理其他确定的片段。每份 TTS 稿文末默认加入一个 `<#0.8#>`，供后续音频拼接时留出间隔；字符串对齐 JSON 不等于音频时间轴。只有用户明确要求停在文本阶段时在此交付；默认继续配音。

## 流程二：配音生成

1. 读取 `docs/tts.md`。需要 Python 3.9+，无第三方 Python 依赖；用户在根目录 `.env` 或环境变量中配置 `MINIMAX_API_KEY`。国际站账号还需匹配接入地址。已有环境变量优先于 `.env`。配置缺失时说明具体缺少什么，不索取或回显聊天中的密钥。
2. 把已准备的 TTS 文本原样交给脚本。默认模型与参数可用；未固定音色时优先自动选系统中文音色，用户指定时用 `--voice-id` 或 `MINIMAX_VOICE_ID`。脚本可自动选音色，无需每次先执行 `voices`。

   ```bash
   python3 tools/minimax_tts.py voices
   python3 tools/minimax_tts.py synthesize --text-file <任务目录/tts/源稿_TTS.txt> --output-dir <任务目录/audio/001>
   ```

3. 单次上限为 9000 个 UTF-16 字符，不能用字节数、token 数或拆分工具显示的 Python 字符数代替。超长先分段，脚本不会截断或自动拼接音频。
4. 标准输出为 JSON。`ok: true` 表示音频已保存；`status: partial` 表示字幕缺失或失败，必须查看 `warnings`，不当作完整字幕成功。运行失败退出码 1，标准错误为 JSON；参数用法错误退出码 2。
5. 合成可能计费，网络超时也可能已计费，不自动重发请求。已有响应时优先恢复：

   ```bash
   python3 tools/minimax_tts.py recover --response-file <原输出/response.json> --output-dir <新的恢复目录>
   ```

6. 保存 MP3、SRT、`timeline.json`、`segments.csv`、请求及结果记录。字幕缺失时只报告实际已有文件，不伪造字幕。临时字幕链接可能过期。

## 完成音频与交接

1. 多段稿按顺序合成，保持同一音色与参数。每次返回立即记录结果和已成功阶段；失败不影响其他已经保存的配音，不自动重复失败请求。
2. 检查各段音频能否解码、实际时长和段落顺序。默认按拆分段交付独立音频，不拼接；各段保留自己的字幕和从零开始的时间轴。文末停顿已经包含在 TTS 输入中，不重复添加间隔。
3. 保留服务原始字幕；段落内部按字符插值的时间只能标为估算，不能宣称逐字强制对齐。没有字幕时交付已有音频并说明缺失，不伪造时间轴。只有后续明确需要合并时，才按实际解码时长累加偏移并合并字幕。
4. 全部配音完成后运行交接脚本，不为单个任务另写检查脚本：

   ```bash
   python3 tools/audio_handoff.py <任务目录> --source <实际用于拆分的源稿.md>
   ```

   脚本按 `parts/`、`tts/<名称>_TTS.txt`、`alignment/<名称>.alignment.json`、`audio/NNN/` 的约定自动配对，只读取已有产物，不调用配音接口。它检查每段 `result.json` 成功、请求文本与 TTS 稿一致、alignment 通过、音频可解码、实际时长、结尾静音、字幕范围与音色一致，然后写入 `manifest.json`（含各段 `decodedDurationMs`、排除提示后的章节标题 `headings`、视频提示及位置 `videoHints` 和配音顺序，保留已有字段）、`音频检查.json` 和 `音频交接.md`。有段落未完成时退出码为 1，`stage` 记为 `audio_partial`。
5. 任务目录保留上述约定目录、第二步分镜草案及交接文件；不另建重复的 alignment 目录或一次性脚本。`改动说明.md` 记录口播用途、初稿、科普文字稿、适配稿与拆分稿的路径关系及改写说明、公式省读理由和展示提示位置，与音频一同交接；`--source` 必须指向实际拆分的适配稿（仅补提示时为最新副本）。
6. 交付重点是各段可播放音频和文件路径，附简短检查结果与必要警告，注明是否依赖视频展示公式；到音频完成即停止。视频由另一模型在后续视频任务中处理，不自动渲染视频。

文章或适配稿后续改动时，按 [稿件更新与产物复用](video_hints.md#稿件更新与产物复用) 更新拆分、alignment 和交接；不可沿用不匹配的检查结果或音频。

## 检查边界

- 原文与朗读稿的 alignment 必须由 `tools/check_tts.py --alignment-dir` 纯脚本完成，不调用模型做匹配，不用模型判断替代检查结果。第二步负责必要视听调整及内容完整性审阅，第三步结合画面负责读法与讲解节奏审阅，必要的台词补充须先回写适配稿，不用模型替代字符串匹配。
- 修改配音工具后运行 `python3 -m unittest discover -s tests -v`，测试不访问真实 MiniMax；真实合成仅用于用户要求的音频任务。
- 未试听时如实说明；格式检查、音频解码检查和内容试听是不同阶段。不展示 API key，不提交 `.env`、输出和临时凭据。
