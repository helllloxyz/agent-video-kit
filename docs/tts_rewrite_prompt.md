# 文稿的 TTS 音频化 Prompt

将已确定的视听适配稿转换为 MiniMax `speech-2.8-hd` 朗读纯文本。画面、分镜和必要桥接由 [视频与分镜 Prompt](manuscript_to_storyboard_prompt.md) 完成；本步骤只做音频化所需的转换。

**尽量维持原文。** 除格式、公式读法、必要发音转换、经清单确认的英文补注省读和停顿标签外，台词文字、标点与顺序逐字保留。不要为口播整体润色、过度通俗化或重新设计画面。围绕已有画面补充必要解释时，先更新适配稿和相关分镜，再以更新后的版本提取、拆分和检查，不让新增台词只存在于 TTS。

## 配合画面讲解

先读适配稿的 `visual` 和分镜草案，再生成口播，不能先删注释而忽略画面设计。针对复杂公式、推导、图表和图片，从看图讲解的角度确定读法：引导观众找到当前对象、符号或行列，顺着画面变化说明关键关系、推理依据及结果。保留原文术语、条件与严谨程度，已有解释直接沿用。

画面能传达大量细节，口播不用逐项复述，但也不以最短为目标。对照每个展示节拍，检查观众是否来得及定位、比较、理解，再进入下一步；不要用一句概括覆盖多步推导或整张复杂图表。朗读期间可逐步展开、跨句保留关键材料；停顿用于必要观察，不能用长静音代替缺失的解释，也不能靠重复或无关扩写拖时间。

公式读法在本步骤内完成。若需要补充图表说明、推理解释或桥接，先按第二步原则局部修订适配稿，同步分镜与改动说明，再重新生成受影响的拆分稿、TTS 和 alignment；这是对上一阶段的必要回修，不是另起一版口播。配音前做文字与展示节拍的复核，配音后再用实际音轨检查停留时间，不能把估算当作已验证。

## 提取与格式

- 仅从 TTS 排除 HTML 注释；旧标记须先在源稿中迁移，完整的公式、推导、表格、图片引用与制作安排保留在适配稿、拆分稿及交接中。
- 视频用途下井号标题默认不读，检查加 `--visual-headings`；纯音频、明确读标题或复查原有已读标题音轨时保留标题文字，不加该参数。`>` 段落只去前缀、保留台词。
- 去掉加粗、反引号等控制语法，链接读显示文字，地址另记；网址本身是讲解对象时保留必要读法。有序列表格式编号可读为“第一”“第二”等，已有中文编号不重复增加；无序列表去符号，不增串联句。
- 英文半角括号转全角，避免被 MiniMax 当作标签；半角括号仅用于允许的语气标签。数字、年份、单位、百分数及正文中的字母、符号、集合花括号原样保留，不改数值。
- 确实无法正常发音的写法仅做必要转换，逐处记录原文与读法。表格按已确定的行列关系朗读；图片说明或术语读法不明确时列为待确认，不自行概括图片、推导新含义或补知识背景。脚本不支持的差异不能靠扩大豁免来蒙混通过，须单独处理。

## 括号补充说明的口播处理

逐处连读括号前后正文，判断括号内容是解释、条件、重复译名还是制作备注。把半角括号换成全角只解决格式问题，不能解决插入语听起来突兀的问题；不机械读“括号”“括号结束”，也不一律删除括号及其内容。

- **需要听懂的补充解释**：在适配稿阶段局部融入正文，按实际关系使用“也就是”“例如”等连接，或改成紧邻的独立短句，再顺畅接回主句。不机械地给每处括号加“也就是说”，不改变因果、限定范围或确定程度。
- **条件、范围、例外、否定、数字与单位**：保留完整信息，并放在听众能明确判断其修饰对象的位置，不能当作可有可无的补注省读。
- **中文名称后的重复英文**：按下节的专用规则省读并保留字幕；`caption_annotations.json` 不能用于任意中文解释的删改。
- **来源、旁注或制作备注**：逐处判断是否参与论证。确实无需朗读的材料，在适配阶段明确保存位置与展示安排；不能只从 TTS 中静默删除，不能假设移入 `visual` 后字幕会自动保留。纯音频不得把理解所需的信息交给画面。
- **公式中的括号、函数参数、区间等数学记号**：按公式语义处理，不当作插入语拆掉；本来连读自然的简短补充无需强行改写。

例如，`这个结论（仅在独立条件下成立）不能直接推广。` 可在适配稿中改为 `这个结论仅在独立条件下成立，不能直接推广。`；`这种变换（也就是旋转坐标轴）不改变长度。` 可改为 `这种变换也就是旋转坐标轴，它不改变长度。`。这些是局部表达调整，不授权整体重写。

上述文字或标点调整须先落实到任务内的适配稿副本，记录原句、改后句与理由，保留输入原稿，再重新拆分、提取和严格校验；纯音频在任务内的朗读适配副本完成，不必新增分镜。若用户禁止改动已确定的源稿或仅允许补提示，列出所需调整，不在 TTS 中绕过限制。仅改流程提示词的任务不回修任何既有稿件或产物。

## 英文补注：不朗读，字幕保留

中文姓名或术语后仅作补充的英文姓名、译名、术语，默认不进入 TTS，但适配稿与字幕完整保留。例：`阿采尔（J. Aczél）` 只读“阿采尔”；`左不变哈尔测度（Haar Measure）` 只读中文名称；`“左不变微分形式”（Maurer-Cartan 形式）` 省略整个重复补注。用户明确要求读英文时照读，不启用相应省读条目。

先逐处审阅，确认括号确为重复补注；不得自动删除所有含英文的括号。必要条件、公式变量、缩写首次定义及作为讲解对象的英文仍保留必要读法。不要把补注移入 visual 后以为字幕会自动恢复。

在任务根目录保存 `caption_annotations.json`，明确列出原文与唯一允许的读法：

```json
[
  {"sourceText": "阿采尔（J. Aczél）", "spokenText": "阿采尔"},
  {"sourceText": "左不变哈尔测度（Haar Measure）", "spokenText": "左不变哈尔测度"}
]
```

`sourceText` 为中文名称及紧随其后的完整英文括号补注，`spokenText` 必须是原样保留的名称前缀；含引号时一同保留。此清单不是自由改写表。运行检查时追加 `--caption-annotations <任务目录/caption_annotations.json>`，目录检查可共用整份清单，各段仅匹配其中实际出现的文本。补注与其他可替换片段紧邻而无法独立定位时，检查会拒绝，须明确处理源稿边界，不能扩大豁免。

脚本将其记录为 `alignment.segments` 中的 `caption_annotation`，保留完整原文、源行号和中文读法的字符范围；既不能省略中文名称，也不能借此改写周围正文。无清单时仍按普通正文严格核对。清单中的内容经语义审阅后才能使用，脚本不判断英文是否只是重复说明。

字幕工具在 `--captions spoken` 和 `--captions source` 两种模式下均保留这些已对齐补注，随中文名称显示，不新增音频时间；spoken 模式不会因此恢复其他公式。服务原始字幕仍原样保存，英文由后续视频字幕准备恢复。长英文造成单条字幕过宽时，在视频阶段检查排版与阅读负担。清单与 alignment 一并交接；改动后重新检查，不沿用旧映射。

## 公式读法

转换范围限于 `$...$`、`$$...$$`、`\(...\)`、`\[...\]` 内的公式，不改公式外的台词和标点。结合上下文选择准确读法，画面中的完整 LaTeX 始终保留。

- 简单关系、首次引入且需要说明的符号，简短读出。
- 较长公式按适配稿已确定的讲解意图表达关系或变化，不机械念每个下标和等号；不要借公式转换改写整段论述。
- 相邻台词已表达同一含义，且已有完整展示安排时，可不读该公式；去掉后不得留下残句或模糊指代。不能满足时保留足够的准确讲解，或返回分镜阶段修订，不临时删正文。

保留变量、条件、范围、否定、方向、运算顺序和确定程度；不凭公式外形猜术语或补新结论。介绍符号写法时读必要的上下标、撇号等。空读法逐处记录理由、展示位置及对应台词；缺少画面承接时返回上一阶段补齐。

纯音频可直接处理已定稿文章，不必制作分镜；完整表达必要公式与条件，不依赖画面省读。若表格或图片包含必须另写解释才能听懂的信息，先补全并确定源稿，再音频化，不把制作指令直接念出。

## 停顿与语气

使用 `<#秒数#>`，范围 0.01–99.99 秒，最多两位小数。逐段审阅语义节奏，除文末间隔外，也要为段内的换气、推理转换和理解留白安排必要停顿。语速正常不代表节奏舒适；密集公式、连续推导、概念辨析和设问尤其需要检查，不能默认只有文末一个停顿就足够。

以下时长是按语义选择的起点，不是每处必须套用的配额：

| 语义位置 | 建议停顿 | 目的 |
| --- | --- | --- |
| 核心主题结束、大章节或推导方法切换 | 0.6–0.8 秒 | 消化结论并进入下一主题 |
| 密集数学表述之后、转入直观解释之前 | 约 0.5 秒 | 理解关系、观察画面后接上解释 |
| 推导中一个完整步骤结束、进入下一步之前 | 0.4–0.6 秒 | 区分推理层次与依据 |
| 设问之后、关键结论或辨析完成之后 | 0.4–0.5 秒 | 留出思考时间，不立即抢接下一句 |
| 并列假设或多点罗列的完整项目之间 | 约 0.3 秒 | 分清项目，保持连贯 |

先考虑标点已有的自然停连，再判断是否需要显式停顿；不每句、每行推导都加，不按字数或注释长度批量插入。停顿放在完整语义边界，不割裂主谓、条件与结论、数字与单位或公式内部。相邻位置承担同一转换时只保留一次合适停顿，不叠加各档时长；不要用长静音弥补缺失的解释。

内部停顿位于可发音文字之间，不在文件开头，不连续叠加。每份独立 TTS 稿文末默认一个 `<#0.8#>`，之后仅有空白；用户可指定其他时长或取消。不为插停顿改标点或拆句。

仅允许 `(breath)`、`(emm)`、`(chuckle)`，用于必要换气或台词已有的犹豫、轻笑语气，不改变作者声音。每千字通常零至两处，不设配额；公式内部不加，不与停顿密集堆叠。

## 检查与交付

1. 读取指定的实际适配稿和已有分镜、改动说明，复用已完成产物。保留源文件，沿用唯一 `outputs/<任务>/`；目录输入按相对路径和文件名自然排序，排除项目配置及已生成文件，不覆盖历史输出。
2. 按 [音频流程](audio_workflow.md) 将适配稿拆分到 `parts/`，每份源稿最多 3000 字符，包含注释和完整上屏材料；单章超限按流程处理，不能删推导凑长度。生成 UTF-8 的 `tts/<拆分稿名>_TTS.txt`，另查 9000 UTF-16 字符限制。纯视觉段落不提交空文本合成。
3. 使用对应拆分稿运行检查：

   ```bash
   python3 tools/check_tts.py <任务目录/parts> <任务目录/tts> \
     --alignment-dir <任务目录/alignment> --visual-headings
   ```

   读标题时去掉 `--visual-headings`。脚本排除注释与格式，忽略空白和允许标签，公式、列表编号、表格、代码和图片是可替换片段，其他台词逐字核对。alignment 记录源行号、TTS 字符范围与 `videoHints`，不含音频时间；它不验证文章到适配稿的内容完整性。匹配必须由脚本完成，不由模型代替。
4. 修正全部错误并重跑，逐条处理警告，审阅公式含义、数字、条件和发音，连读检查括号补充是否突兀、段内是否连续过密或停顿过碎，并对照 visual 与分镜检查讲解是否覆盖必要的观察步骤、是否过短。不能把可替换片段当作自由改写区，也不能因检查通过就声称语义或画面已验证。未解决项单列，不宣称可完整合成。
5. 更新 `改动说明.md`，保留上一阶段记录，补充适配稿、拆分稿、TTS 的路径关系，实际源行、公式与发音读法、空读理由、标题模式、括号说明的处理记录、内部与文末停顿数量及代表性位置的理由、其他格式与标签数量、检查结果。停顿数量不作为质量指标；未试听只能报告节奏设计与文本检查完成。交付 TTS、检查记录和待确认项，完整适配稿与分镜一同保留。
6. `audio_handoff.py --source` 与 `manifest.source` 指向实际拆分的适配稿（纯音频时为实际采用的源稿）。是否配音或制作视频按 `AGENTS.md` 和用户范围执行，未合成或试听时如实说明。
