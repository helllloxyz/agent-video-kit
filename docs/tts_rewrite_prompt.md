# 适合 TTS 的文稿改写 Prompt

将用户已经校对过的 Markdown 讲稿，转换为适合 MiniMax `speech-2.8-hd` 朗读的纯文本。仅在任务需要讲稿朗读适配时使用本 Prompt；是否生成配音或视频，由根目录 `AGENTS.md` 和用户本次要求确定。用户当次的明确要求优先。

## 核心边界：只适配朗读，不编辑文稿

源文是用户已经检查过的定稿。正文措辞、事实、观点、语气、论证、例子、顺序、限定词和确定程度必须保留。

允许改动仅有四类：

1. 将 Markdown 等书面格式转换为朗读形式，并排除 `<@ ... >` 视频制作提示。
2. 将 LaTeX 公式片段替换为准确、简短、适合配合画面讲述的表达；满足下文条件时可只展示、不朗读。
3. 将正文中的英文半角括号改为全角括号；对残留 LaTeX 命令等确实无法朗读的写法做最小转换。
4. 按原有结构插入适量停顿和极少量语气标签。

**除上述片段外，正文逐字保留。** 句子即使很长、重复、拗口，或者从写作角度可以优化，也不拆句、不润色、不纠错、不换词、不调整标点。

不新增开场白、总结、互动话术或知识背景。不删重复内容，不省去中英文对照，不替换人名，不改变作者声音。不对内容做事实检查或数学纠错；转换时发现无法可靠判断的符号含义，仅记录到独立说明中。

## 格式转换

- `<@ ... >` 内是分镜、动画等制作提示，不是朗读正文。完整排除标记及内容，不转写为解说，不按其长度添加停顿；原稿与拆分稿保留，在改动说明中记录提示及源位置。普通 `<...>` 不作为此类提示，`<#秒数#>` 仍按停顿规则处理。跨行、作用范围及语法边界见 [视频制作提示约定](video_hints.md)。
- 去掉标题的井号、加粗标记、反引号、引用前缀、公式定界符等控制语法，保留原有文字及顺序。
- 保留原有章节、小标题、段落及其层次，不改标题措辞，不重新组织结构。
- 有序列表可以按语境将 `1.`、`2.` 等格式标记读作“第一”“第二”等。已有中文编号时不重复增加。
- 无序列表去掉项目符号，逐项保留文字，不额外增加序号或串联句。
- 正文中的英文半角括号 `(`、`)` 一律改为全角 `（`、`）`，避免 MiniMax 把括号内容当作发音覆盖或语气标签。公式读法里也不使用半角括号。输出中半角括号只用于下文允许的三个语气标签。
- Markdown 链接转换为其显示文字。参考链接地址保存在改动说明中；如果网址本身是讲解对象，则保留其含义并给出必要读法。
- 表格可以将单元格内容按明确的行列关系线性排列，必要时重复原有表头，不能新增比较、概括或结论。
- 代码、图片、脚注等若已有明确的朗读含义，仅做格式转换；若需要自行补充内容才能讲清，不猜测、不擅自删去，在说明中列为待确认项。
- 修复明显的 Markdown 格式问题仅限控制标记、缩进和分隔符，不以修复格式为由改正文。

## 公式：只替换公式所在片段

### 转写范围

只有 LaTeX 公式片段需要转写，即 `$…$`、`$$…$$`、`\(…\)`、`\[…\]` 包住的内容，每一处视为一个可替换片段。

正文里没有公式定界符的字母、符号和简单表达式，如 `AB`、`A + B`、`A'`、`[0, 1]`、`{0, 1}`、`17 世纪`，原样保留，交给 TTS 直接读。正文集合的花括号也必须保留；检查脚本只豁免与原稿正文精确匹配的花括号，公式转写中残留的花括号仍报错。读起来生硬一点、不够口语化可以接受，不为此改写。

可以阅读上下文确定公式含义，但**上下文只用于理解，不属于编辑范围**。原公式前后的句子、标点和段落文字不得改动，不得在公式前后增加连接词或解释句，也不得把公式的解释扩展到这些文字中。

### 默认用途：配合视频的简短口播

本项目默认按后续有视频画面的用途转写，即使本次只交付音频，也让完整公式由画面承载，口播说明当前最值得关注的关系或变化。交付时注明这是配合视频使用的口播。用户明确要求纯音频、脱离画面也能听懂或逐项读公式时，改用下文的完整读法；完成到哪个制作阶段仍由任务路由决定。

逐处选择最短且足以支撑当前讲解的表达，不为字数目标牺牲含义：

1. **短读**：简单关系、新出现且正在介绍的符号，直接简短读出，如“y 等于 x 的平方”。
2. **概括关系或变化**：长公式、重复公式、多行推导，优先说清“这一式表达什么”或“这一步变了什么”。只概括原式及上下文已明确的内容，不重念每个下标、每层括号或每行等号。
3. **只展示、不朗读**：相邻正文已经说清同一含义，公式只是书面展开或重复展示时，可将该公式片段转为空。仅限去掉后正文仍完整、指代清楚、讲解不断裂的情况；不能留下“得到：。”或“其中，是……”这样的残句。遇到这种情况应保留短读，不越界修改公式外的正文。

### 准确性与画面分工

- 原稿中的 LaTeX 一字不改，完整公式、条件和符号在画面中保留。口播可省去观众能直接看见、且不影响当前理解的机械枚举；这不代表可以改写数学关系。
- 首次引入且理解所必需的量、此次发生变化的条件或范围、否定、方向和运算顺序，要在口播中说清，或由紧邻正文明确交代。已明确且未变化的条件不必反复念；不得让简读听起来像无条件成立、可以交换顺序或默认独立。
- 术语与概括须有原式或上下文依据。例如 `P(A | B)` 可说“在 B 条件下，A 的概率”；只有 `(A|B)` 且上下文未定义含义时，不自行补“概率”。不要推导、计算、改写原式或增加原稿没有的结论，不凭公式外形猜定理名称。
- 不机械套用“如图所示”“就是这个公式”。需要指向画面时，优先说出正在关注的量、关系或变化，让语音提供阅读重点。
- 如果原文正在介绍符号写法，就读出必要的上下标、撇号、横线等；普通讲解无需反复念符号结构。字母通常原样保留，不统一替换成中文谐音。
- 多行推导可用一句话概括已明确的变形过程或结果，不要求第一行完整读、之后逐行读等号。关键推理和成立条件不能以“看公式”为由省去。
- **凡依赖画面而省读的公式，必须有对应的展示提示**：说明定位、完整公式、口播重点和展示顺序；已有提示足够时直接复用。按 [公式展示提示与任务副本](video_hints.md#公式展示提示与任务副本) 在任务副本补充 `<@ ... >`，不能只写在改动说明里，更不能写进 TTS。

### 纯音频或逐项朗读

此模式不使用“只展示、不朗读”，也不依赖“这一项”等画面指代。完整表达变量、条件、上下标、撇号、否定、关系符、正负号、求和或积分范围，以及运算和函数输入顺序。多行推导按原顺序读，可用省略重复左端的“等于……”衔接，确保听者能恢复关系。仍以自然、无重复的读法为准。

### 示例

以下均指公式定界符内的片段，需按上下文判断，不能全局机械替换。视频简读示例：

| 原式与上下文 | 视频口播 | 对应画面提示要点 |
| --- | --- | --- |
| `y=x^2`，首次引入 | y 等于 x 的平方 | 完整展示原式，突出平方项 |
| `\sum_{i=1}^{n}x_i`，已说明是这 n 个数 | 把这些数加起来 | 展示原式，依次突出各项及求和范围 |
| `P(AB\mid C)=P(A\mid C)P(B\mid AC)`，正文已说明固定条件 C | 联合概率拆成两个条件概率的乘积 | 展示完整原式，对应突出两因子，特别标出第二项条件中新增的 A；不得画成独立事件的乘法 |
| `F(F(x,y),z)=F(x,F(y,z))`，上下文已定义 F 并讨论结合方式 | 结合方式变了，结果不变 | 保留完整等式，对比两侧分组，保持 x、y、z 的输入顺序 |
| 独立公式重复表达上一句已讲清的结论，去掉后正文仍完整 | 不朗读该公式片段 | 在上一句讲结论时展示完整原式，继续保留供观察 |

需要读出具体符号、条件或范围时，可采用以下读法，不要求视频口播一律展开到这个程度：

- `P(A | B)` → “在 B 条件下，A 的概率”。
- `P(AB | C) = P(A | C) P(B | AC)` → “在 C 条件下，A 且 B 的概率，等于在 C 条件下 A 的概率，乘以在 A 且 C 条件下 B 的概率”。
- `(AB|C)`，原式没有 P → “AB 竖线 C”或“C 条件下的 A 且 B”，不加“概率”。
- 布尔代数中的 `AB` → “A 且 B”；`A+B` → “A 或 B”。数值代数中则按乘法和加法读。
- `\overline{A}` 在逻辑否定语境读“非 A”；在均值等语境按实际含义处理。
- `A'` → “A 撇”；导数语境需按该处定义读。
- `x_i^2` → “x 下标 i 的平方”。
- `\frac{a+b}{c}` → “a 加 b 的和，除以 c”。
- `\sum_{i=1}^{n}x_i` → “对 x 下标 i 求和，i 从一到 n”。
- `\int_0^1 x^2\,dx` → “从零到一，对 x 的平方关于 x 积分”。
- `F(F(x,y),z)=F(x,F(y,z))` 在纯音频中可读成：“先把 x 和 y 输入函数 F，再把结果与 z 输入 F，等于先把 y 和 z 输入 F，再把 x 与结果输入 F。”保持两侧的输入顺序。

### 数字和待确认项

数字、年份、单位、百分数默认保留阿拉伯数字原样，TTS 通常能读对；不得改数值。

遇到无法可靠解析、符号未定义或有歧义的公式，保留原片段，记录源位置和问题，继续处理可确定的部分，并在交付时明确该输出仍有待确认项，不宣称可直接完整合成。

## MiniMax 停顿

使用原样标记 `<#秒数#>`，如 `<#0.5#>`。单位为秒，范围 0.01 至 99.99，最多两位小数。

- 大章节转换：参考 0.7 至 0.9 秒。
- 小节转换：参考 0.4 至 0.6 秒。
- 需要观察公式的讲解边界：必要时参考 0.3 至 0.5 秒，不因原式长或推导行数多就逐行加停顿。简读后要在分镜中检查阅读时间，不能用大量静音替代展示安排。
- 普通段落以原有标点和换行为主，不每段、每句都插标记。

以上是可调整的起始设置，不是每处都必须标记。根据原 Markdown 层级选择少量结构边界，不能制造新的内容层级。

内部停顿标记必须夹在可发音文字之间，不在文件开头，不连续使用。每份输出文末默认保留一个 `<#0.8#>`，包括拆分后每份独立 TTS 稿，供不同配音片段拼接时留出间隔；用户可指定其他时长或取消。文末停顿后只能有空白，不追加语气标签；不要与已有文末停顿叠加。同一边界不堆叠停顿；已有标点、换行的自然停顿也要考虑。允许在原文标点后插标记，禁止因此改写原标点或拆句。

## 极少量语气标签

仅允许以下英文半角标签：

- `(breath)`：必要的自然换气，少量放在已有句子或段落边界。
- `(emm)`：只有原文已有明确的犹豫、思考语气时才考虑使用。
- `(chuckle)`：只有原文确实已有轻笑、幽默或自嘲意味时才考虑使用；严肃推导通常不用。

不要求三种都出现。每一千字通常零至两处即可，不能为了配额硬加。不得新增“嗯”“啊”“那么”“其实”“对吧”等语气词或连接语，也不得用标签改变原文情绪。公式内部不插语气标签；同一位置不密集堆叠语气标签与显式停顿。已有标签先核对，避免重复插入。

## 文件处理和交付

1. 读取用户提供的实际文件。输入为文件时处理整份；输入为目录时默认递归处理 `.md`、`.markdown` 文件，按相对路径及文件名中的数字自然排序。排除版本控制、项目配置、`outputs` 目录，以及文件名主干以 `_tts` 或 `_TTS` 结尾的已生成文件（如 `001_讲稿_tts.md`、`001_讲稿_TTS.txt`）。用户明确指定的文件不因名称特殊而跳过。
2. 不修改用户源文件，不自动处理用户未指定的其他讲稿，不改用户的全局配置。需要补公式展示提示时，按视频提示约定建立任务副本，只增补提示，正文和 LaTeX 保持原样。本 Prompt 只负责文本适配；配音与视频步骤由根目录 `AGENTS.md` 编排。
3. 在本项目根目录的 `outputs` 下，为本次任务创建唯一子目录，如 `2026-10-11_103500`。如有用户指定或当前环境规定的输出目录，优先遵循。源目录的相对结构保留，每份讲稿生成“原文件名_TTS.txt”，编码为 UTF-8，不覆盖历史输出。
4. 同时生成一份 `改动说明.md`：列出源文件、任务副本与输出文件对应关系，注明视频简读或纯音频用途；记录公式和其他可替换片段的“原文 → 转换结果”及源行号。公式逐处注明短读、概括或不朗读、所依赖的上下文及对应展示提示位置；记录已有和新增的 `<@ ... >` 提示及源位置；记录格式转换和停顿、语气标签数量；附上检查脚本的结果摘要；存在待确认项时单独列出。说明不混入 TTS 正文。
5. 交付简短报告、文件链接和待确认项。只完成文本适配时，不声称已试听或验证合成效果。

## 保存前核对

1. 先标识并排除 `<@ ... >` 视频制作提示，再标识公式、格式控制符和半角括号；其余文字直接复制，避免凭记忆重写整篇。
2. 写完输出后，在本项目根目录运行检查脚本：

   ```bash
   python3 tools/check_tts.py <源文件或源目录> <输出文件或本次输出目录> --alignment-dir <本次任务目录/alignment>
   ```

   脚本排除源稿视频制作提示，忽略空白、停顿标记和允许的语气标签，把源文中的公式、有序列表编号、表格、代码、图片视为可替换片段，其余正文逐字比对；同时检查 TTS 中残留的视频提示、停顿格式与位置、语气标签、半角括号和残留的 Markdown 或 LaTeX 语法。`--alignment-dir` 导出正文和替换片段的原稿行号、TTS 字符范围及对应文本；提示单独保存为 `videoHints`，不进入可替换片段。中英文原样按字符串顺序匹配，不自动接受润色差异，也不推断音频时间。
3. 脚本报告的“错误”必须全部处理：越界改动恢复原文，格式问题修正后重跑，直到通过。确属有意且符合本规则的差异，例如待确认片段保留原样，在改动说明中逐条说明。“警告”逐条判断是否需要修改。
4. 逐条审阅脚本列出的“可替换片段对照”：公式短读或概括符合原式和上下文，不夹带新结论；必要条件、运算顺序、作用范围和数字准确。视频简读省略的细节有完整公式和展示提示承接。空读法警告必须逐条核查，在说明中记录不朗读的理由、正文是否完整及展示位置；不能把脚本通过当作语义审阅完成。纯音频模式不接受依赖画面的省读。
5. TTS 文件只包含需要朗读的文本及允许标签，不包含编辑说明、路径、提示词或核查记录。
