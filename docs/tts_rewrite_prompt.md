# 适合 TTS 的文稿改写 Prompt

将用户已经校对过的 Markdown 讲稿，转换为适合 MiniMax `speech-2.8-hd` 朗读的纯文本。仅在任务需要讲稿朗读适配时使用本 Prompt；是否生成配音或视频，由根目录 `AGENTS.md` 和用户本次要求确定。用户当次的明确要求优先。

## 核心边界：只适配朗读，不编辑文稿

源文是用户已经检查过的定稿。正文措辞、事实、观点、语气、论证、例子、顺序、限定词和确定程度必须保留。

允许改动仅有四类：

1. 将 Markdown 等书面格式转换为朗读形式。
2. 将 LaTeX 公式片段替换为准确、适合口头讲述的表达。
3. 将正文中的英文半角括号改为全角括号；对残留 LaTeX 命令等确实无法朗读的写法做最小转换。
4. 按原有结构插入适量停顿和极少量语气标签。

**除上述片段外，正文逐字保留。** 句子即使很长、重复、拗口，或者从写作角度可以优化，也不拆句、不润色、不纠错、不换词、不调整标点。

不新增开场白、总结、互动话术或知识背景。不删重复内容，不省去中英文对照，不替换人名，不改变作者声音。不对内容做事实检查或数学纠错；转换时发现无法可靠判断的符号含义，仅记录到独立说明中。

## 格式转换

- 去掉标题的井号、加粗标记、反引号、引用前缀、公式定界符等控制语法，保留原有文字及顺序。
- 保留原有章节、小标题、段落及其层次，不改标题措辞，不重新组织结构。
- 有序列表可以按语境将 `1.`、`2.` 等格式标记读作“第一”“第二”等。已有中文编号时不重复增加。
- 无序列表去掉项目符号，逐项保留文字，不额外增加序号或串联句。
- 正文中的英文半角括号 `(`、`)` 一律改为全角 `（`、`）`，避免 MiniMax 把括号内容当作发音覆盖或语气标签。公式读法里也不使用半角括号。输出中半角括号只用于下文允许的三个语气标签。
- Markdown 链接转换为其显示文字。参考链接地址保存在改动说明中；如果网址本身是讲解对象，则保留其含义并给出必要读法。
- 表格可以将单元格内容按明确的行列关系线性排列，必要时重复原有表头，不能新增比较、概括或结论。
- 代码、图片、脚注等若已有明确的朗读含义，仅做格式转换；若需要自行补充内容才能讲清，不猜测、不擅自删去，在说明中列为待确认项。
- 修复明显的 Markdown 格式问题仅限控制标记、缩进和分隔符，不以修复格式为由改正文。

## 公式：只替换公式所在片段

### 转写范围

只有 LaTeX 公式片段需要转写，即 `$…$`、`$$…$$`、`\(…\)`、`\[…\]` 包住的内容，每一处视为一个可替换片段。

正文里没有公式定界符的字母、符号和简单表达式，如 `AB`、`A + B`、`A'`、`[0, 1]`、`17 世纪`，原样保留，交给 TTS 直接读。读起来生硬一点、不够口语化可以接受，不为此改写。

可以阅读上下文确定公式含义，但**上下文只用于理解，不属于编辑范围**。原公式前后的句子、标点和段落文字不得改动，不得在公式前后增加连接词或解释句，也不得把公式的解释扩展到这些文字中。

### 读法原则

- 读法只表达公式字面已有的内容，沿用原式的记号和措辞，不补原式没有的名词或概念。例如原式写 `P(A | B)`，可以读出“概率”；原式写 `(A|B)`、`A \mid B`，没有 P，就不得自行加上“概率”“合情性”等词。
- 简单公式接近字面读即可。较长、嵌套较多、直接读 LaTeX 结构会很别扭的公式，可以改成老师讲课时会说的口语读法。听众有字幕对照，读法以顺口、不错义为准，不必为消除所有口语歧义而加长解释。
- 不要推导、计算、简化公式，不增加原式没有的性质或结论，不重复讲同一个公式。
- 必须保留所有变量、条件、上下标、撇号、否定、等号、不等号、正负号、求和或积分范围，以及运算和函数输入顺序。不可暗中假设交换律、独立性等额外条件。
- 如果原文正在介绍符号写法，可以读“竖线”“上方加横线”等；普通推导优先直接说数学含义。无须每次补充符号定义。
- 字母通常原样保留，不统一替换成中文谐音。
- 多行推导（如 `aligned` 环境）：第一行完整读出；之后每行以该行的关系符开头，多为“等于”；行与行之间可加 0.3 至 0.5 秒停顿。

### 示例

以下均指公式定界符内的片段，需按上下文判断，不能全局机械替换：

- `P(A | B)` → “在 B 条件下，A 的概率”。
- `P(AB | C) = P(A | C) P(B | AC)` → “在 C 条件下，A 且 B 的概率，等于在 C 条件下 A 的概率，乘以在 A 且 C 条件下 B 的概率”。
- `(AB|C)`，原式没有 P → “AB 竖线 C”或“C 条件下的 A 且 B”，不加“概率”。
- 布尔代数中的 `AB` → “A 且 B”；`A+B` → “A 或 B”。数值代数中则按乘法和加法读。
- `\overline{A}` 在逻辑否定语境读“非 A”；在均值等语境按实际含义处理。
- `A'` → “A 撇”；导数语境需按该处定义读。
- `x_i^2` → “x 下标 i 的平方”。
- `\frac{a+b}{c}` → “a 加 b 的和，除以 c”。
- `\sum_{i=1}^{n}x_i` → “对 x 下标 i 求和，i 从一到 n”。
- `\int_0^1 x^2\,dx` → “从零到一，对 x 的平方关于 x 积分”。
- `F(F(x,y),z)=F(x,F(y,z))` 可读成：“先把 x 和 y 输入函数 F，再把所得结果与 z 按这个顺序输入 F；结果等于，先把 y 和 z 输入 F，再把 x 与所得结果按这个顺序输入 F。”

### 数字和待确认项

数字、年份、单位、百分数默认保留阿拉伯数字原样，TTS 通常能读对；不得改数值。

遇到无法可靠解析、符号未定义或有歧义的公式，保留原片段，记录源位置和问题，继续处理可确定的部分，并在交付时明确该输出仍有待确认项，不宣称可直接完整合成。

## MiniMax 停顿

使用原样标记 `<#秒数#>`，如 `<#0.5#>`。单位为秒，范围 0.01 至 99.99，最多两位小数。

- 大章节转换：参考 0.7 至 0.9 秒。
- 小节转换：参考 0.4 至 0.6 秒。
- 复杂公式前后或多行推导的行与行之间：必要时参考 0.3 至 0.5 秒。
- 普通段落以原有标点和换行为主，不每段、每句都插标记。

以上是可调整的起始设置，不是每处都必须标记。根据原 Markdown 层级选择少量结构边界，不能制造新的内容层级。

内部停顿标记必须夹在可发音文字之间，不在文件开头，不连续使用。每份输出文末默认保留一个 `<#0.8#>`，包括拆分后每份独立 TTS 稿，供不同配音片段拼接时留出间隔；用户可指定其他时长或取消。文末停顿后只能有空白，不追加语气标签；不要与已有文末停顿叠加。同一边界不堆叠停顿；已有标点、换行的自然停顿也要考虑。允许在原文标点后插标记，禁止因此改写原标点或拆句。

## 极少量语气标签

仅允许以下英文半角标签：

- `(breath)`：必要的自然换气，少量放在已有句子或段落边界。
- `(emm)`：只有原文已有明确的犹豫、思考语气时才考虑使用。
- `(chuckle)`：只有原文确实已有轻笑、幽默或自嘲意味时才考虑使用；严肃推导通常不用。

不要求三种都出现。每一千字通常零至两处即可，不能为了配额硬加。不得新增“嗯”“啊”“那么”“其实”“对吧”等语气词或连接语，也不得用标签改变原文情绪。公式内部不插语气标签；同一位置不密集堆叠语气标签与显式停顿。已有标签先核对，避免重复插入。

## 文件处理和交付

1. 读取用户提供的实际文件。输入为文件时处理整份；输入为目录时默认递归处理 `.md`、`.markdown` 文件，按相对路径及文件名中的数字自然排序。排除版本控制、项目配置、`outputs` 目录，以及文件名主干以 `_tts` 或 `_TTS` 结尾的已生成文件（如 `001_讲稿_tts.md`、`001_讲稿_TTS.txt`）。用户明确指定的文件不因名称特殊而跳过。
2. 不修改源文件，不自动处理用户未指定的其他讲稿，不改用户的全局配置。本 Prompt 只负责文本适配；配音与视频步骤由根目录 `AGENTS.md` 编排。
3. 在本项目根目录的 `outputs` 下，为本次任务创建唯一子目录，如 `2026-10-11_103500`。如有用户指定或当前环境规定的输出目录，优先遵循。源目录的相对结构保留，每份讲稿生成“原文件名_TTS.txt”，编码为 UTF-8，不覆盖历史输出。
4. 同时生成一份 `改动说明.md`：列出源文件与输出文件对应关系；记录公式和其他可替换片段的“原文 → 转换结果”及源行号；记录格式转换和停顿、语气标签数量；附上检查脚本的结果摘要；存在待确认项时单独列出。说明不混入 TTS 正文。
5. 交付简短报告、文件链接和待确认项。只完成文本适配时，不声称已试听或验证合成效果。

## 保存前核对

1. 先标识公式、格式控制符和半角括号；其余文字直接复制，避免凭记忆重写整篇。
2. 写完输出后，在本项目根目录运行检查脚本：

   ```bash
   python3 tools/check_tts.py <源文件或源目录> <输出文件或本次输出目录> --alignment-dir <本次任务目录/alignment>
   ```

   脚本忽略空白、停顿标记和允许的语气标签，把源文中的公式、有序列表编号、表格、代码、图片视为可替换片段，其余正文逐字比对；同时检查停顿格式与位置、语气标签、半角括号和残留的 Markdown 或 LaTeX 语法。`--alignment-dir` 导出正文和替换片段的原稿行号、TTS 字符范围及对应文本；中英文原样按字符串顺序匹配，不自动接受润色差异，也不推断音频时间。
3. 脚本报告的“错误”必须全部处理：越界改动恢复原文，格式问题修正后重跑，直到通过。确属有意且符合本规则的差异，例如待确认片段保留原样，在改动说明中逐条说明。“警告”逐条判断是否需要修改。
4. 逐条审阅脚本列出的“可替换片段对照”：每段输出只应是该公式或编号的读法，不夹带新增的连接词、解释或原式没有的概念；条件、运算顺序、作用范围和数字准确；无遗漏或重复。
5. TTS 文件只包含需要朗读的文本及允许标签，不包含编辑说明、路径、提示词或核查记录。
