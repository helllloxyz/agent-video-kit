# 文稿的 TTS 音频化 Prompt

将已确定的视听适配稿转换为 MiniMax `speech-2.8-hd` 朗读纯文本。画面、分镜和必要桥接由 [视频与分镜 Prompt](manuscript_to_storyboard_prompt.md) 完成；本步骤只做音频化所需的转换。

**尽量维持原文。** 除格式、公式读法、必要发音转换和停顿标签外，台词文字、标点与顺序逐字保留。不要为口播整体润色、过度通俗化或重新设计画面。围绕已有画面补充必要解释时，先更新适配稿和相关分镜，再以更新后的版本提取、拆分和检查，不让新增台词只存在于 TTS。

## 配合画面讲解

先读适配稿的 `visual` 和分镜草案，再生成口播，不能先删注释而忽略画面设计。针对复杂公式、推导、图表和图片，从看图讲解的角度确定读法：引导观众找到当前对象、符号或行列，顺着画面变化说明关键关系、推理依据及结果。保留原文术语、条件与严谨程度，已有解释直接沿用。

画面能传达大量细节，口播不用逐项复述，但也不以最短为目标。对照每个展示节拍，检查观众是否来得及定位、比较、理解，再进入下一步；不要用一句概括覆盖多步推导或整张复杂图表。朗读期间可逐步展开、跨句保留关键材料；停顿用于必要观察，不能用长静音代替缺失的解释，也不能靠重复或无关扩写拖时间。

公式读法在本步骤内完成。若需要补充图表说明、推理解释或桥接，先按第二步原则局部修订适配稿，同步分镜与改动说明，再重新生成受影响的拆分稿、TTS 和 alignment；这是对上一阶段的必要回修，不是另起一版口播。配音前做文字与展示节拍的复核，配音后再用实际音轨检查停留时间，不能把估算当作已验证。

## 提取与格式

- 仅从 TTS 排除 HTML 注释；旧标记须先在源稿中迁移，完整的公式、推导、表格、图片引用与制作安排保留在适配稿、拆分稿及交接中。
- 视频用途下井号标题默认不读，检查加 `--visual-headings`；纯音频、明确读标题或复查原有已读标题音轨时保留标题文字，不加该参数。`>` 段落只去前缀、保留台词。
- 去掉加粗、反引号等控制语法，链接读显示文字，地址另记；网址本身是讲解对象时保留必要读法。有序列表格式编号可读为“第一”“第二”等，已有中文编号不重复增加；无序列表去符号，不增串联句。
- 英文半角括号转全角，避免被 MiniMax 当作标签；半角括号仅用于允许的语气标签。数字、年份、单位、百分数及正文中的字母、符号、集合花括号原样保留，不改数值。
- 确实无法正常发音的写法仅做必要转换，逐处记录原文与读法。表格按已确定的行列关系朗读；图片说明或术语读法不明确时列为待确认，不自行概括图片、推导新含义或补知识背景。脚本不支持的差异不能靠扩大豁免来蒙混通过，须单独处理。

## 公式读法

转换范围限于 `$...$`、`$$...$$`、`\(...\)`、`\[...\]` 内的公式，不改公式外的台词和标点。结合上下文选择准确读法，画面中的完整 LaTeX 始终保留。

- 简单关系、首次引入且需要说明的符号，简短读出。
- 较长公式按适配稿已确定的讲解意图表达关系或变化，不机械念每个下标和等号；不要借公式转换改写整段论述。
- 相邻台词已表达同一含义，且已有完整展示安排时，可不读该公式；去掉后不得留下残句或模糊指代。不能满足时保留足够的准确讲解，或返回分镜阶段修订，不临时删正文。

保留变量、条件、范围、否定、方向、运算顺序和确定程度；不凭公式外形猜术语或补新结论。介绍符号写法时读必要的上下标、撇号等。空读法逐处记录理由、展示位置及对应台词；缺少画面承接时返回上一阶段补齐。

纯音频可直接处理已定稿文章，不必制作分镜；完整表达必要公式与条件，不依赖画面省读。若表格或图片包含必须另写解释才能听懂的信息，先补全并确定源稿，再音频化，不把制作指令直接念出。

## 停顿与语气

使用 `<#秒数#>`，范围 0.01–99.99 秒，最多两位小数。章间可参考 0.7–0.9 秒，小节间 0.4–0.6 秒，必要观察边界 0.3–0.5 秒；按现有结构少量使用，不每句、每行推导都加，也不按注释长度加静音。

内部停顿位于可发音文字之间，不在文件开头，不连续叠加。每份独立 TTS 稿文末默认一个 `<#0.8#>`，之后仅有空白；用户可指定其他时长或取消。不为插停顿改标点或拆句。

仅允许 `(breath)`、`(emm)`、`(chuckle)`，用于必要换气或台词已有的犹豫、轻笑语气，不改变作者声音。每千字通常零至两处，不设配额；公式内部不加，不与停顿密集堆叠。

## 检查与交付

1. 读取指定的实际适配稿和已有分镜、改动说明，复用已完成产物。保留源文件，沿用唯一 `outputs/<任务>/`；目录输入按相对路径和文件名自然排序，排除项目配置及已生成文件，不覆盖历史输出。
2. 按 [音频流程](audio_workflow.md) 将适配稿拆分到 `parts/`，每份源稿最多 3000 字符，包含注释和完整上屏材料；单章超限按流程处理，不能删推导凑长度。生成 UTF-8 的 `tts/<拆分稿名>_TTS.txt`，另查 9000 UTF-16 字符限制。纯视觉段落不提交空文本合成。
3. 使用对应拆分稿运行检查：

   ```bash
   python3 tools/check_tts.py <任务目录/parts> <任务目录/tts> \
     --alignment-dir <任务目录/alignment> --visual-headings
   ```

   读标题时去掉 `--visual-headings`。脚本排除注释与格式，忽略空白和允许标签，公式、列表编号、表格、代码和图片是可替换片段，其他台词逐字核对。alignment 记录源行号、TTS 字符范围与 `videoHints`，不含音频时间；它不验证文章到适配稿的内容完整性。匹配必须由脚本完成，不由模型代替。
4. 修正全部错误并重跑，逐条处理警告，审阅公式含义、数字、条件和发音，并对照 visual 与分镜检查讲解是否覆盖必要的观察步骤、是否过短。不能把可替换片段当作自由改写区，也不能因检查通过就声称语义或画面已验证。未解决项单列，不宣称可完整合成。
5. 更新 `改动说明.md`，保留上一阶段记录，补充适配稿、拆分稿、TTS 的路径关系，实际源行、公式与发音读法、空读理由、标题模式、格式与标签数量、检查结果。交付 TTS、检查记录和待确认项，完整适配稿与分镜一同保留。
6. `audio_handoff.py --source` 与 `manifest.source` 指向实际拆分的适配稿（纯音频时为实际采用的源稿）。是否配音或制作视频按 `AGENTS.md` 和用户范围执行，未合成或试听时如实说明。
